# project-handoff · 项目验收与交接

一个 DSH 技能：把「什么算做完」写成可判定的标准，用**三态**诚实地判，在决策点生成交接材料，把结论回写成可检查的约束。

它只回答两个问题：

| 问题 | 靠什么 |
|---|---|
| **做完了没有** | 验收定义 + 三态检查（诚实，不许假通过） |
| **卡住了 / 不满意 / 要换手** | 交接材料 + 约束回写 |

> 完整的构思——为什么这么设计、否掉了什么、还有哪些没验证、以及**一份待审的问题清单**——见 [`docs/concept.md`](docs/concept.md)。

---

## 为什么需要它

做完一件事之后，最容易发生的是这段话：

> 「应该差不多了，我跑了一下，看着没问题。」

「看着没问题」和「做完了」是两件事：

- 测试全绿，手感可能很烂；
- 页面能开，功能可能没接上；
- 文件都在，逻辑可能是空的。

所以这个技能的第一条规矩是：**没检查过的，不许说成通过了。**

## 三态，没有第四种

| 状态 | 含义 | 退出码 |
|---|---|---|
| `PASS` | 跑过、确实对 | 0 |
| `FAIL` | 跑过、确实不对 | 1 |
| `UNVERIFIED` | 没跑 / 跑不了 / 还没实现 | **2** |

- 未注册、未实现、跑不出结论 → 一律 `UNVERIFIED`
- 只要还有未验证项，整体退出码就是 2 → **执行层拿不到假的完成信号**
- 自动检查全绿 ≠ 需求满足，人工栏仍要人看

## 自动 / 人工，两条线不许混

```
## 自动
A1  单元测试全绿
A2  引用的文件都存在
A3  页面无控制台报错        → UNVERIFIED（还没接无头浏览器）

## 人工
M1  键位/按钮/暂停都生效
M2  节奏和手感对不对
M3  文案语气
```

「截图存在」不等于「效果对」。人工项不许伪造成自动项。

## 三种触发点，三种材料

| 触发 | 你想问什么 | 材料重点 |
|---|---|---|
| 看效果 | 这像我想要的吗？ | 改动清单 + 效果证据（截图要附图或可访问链接） |
| 卡住了 | 它搞不定，怎么办？ | 报错原文 + 已试过的动作 + 卡在哪一步 |
| 不满意 | 不对，重来 | 你的**原话**（不必整理）+ 空白点，让接手方追问 |

**「不满意」不要求用户先把话说清楚——把模糊提炼成约束，是接手方的活。**

## 交接材料的共同底座

三份材料都必须带，否则接手方会拿旧状态给新建议：

```
任务目标
基线：当前版本 / 上次交接编号
相关文件：仓库路径（不是「我的桌面上」）
待决问题：1~3 条
自动验收：跑了没、红绿、日志在哪
```

## 回写：约束变更单

```
新增：C5 ……
替代：C2（原「只保留折叠」）→ 改为「折叠 + 移动端不折叠」
判定：什么算通过（可检查，不写「感觉更好」）
确认：执行层复述一遍（readback），不对当场驳回
下一轮：验收清单逐条勾
```

**不写「替代」那一行，约束会越积越多，最后互相打架——比模糊更糟。**

## 边界

| 规则 | 原因 |
|---|---|
| 本地生成可以自动；建 gist / 上传截图 / 推远端**必须单独授权，默认不做** | 离开本地是不可逆的 |
| 连续两次失败只作提醒，同一错误原地重试两次就停 | 有进展时不该被打断 |
| 验收标准必须和代码同仓库 | 放远了必然过期，交接的「基线」就对不上 |
| 通用脚本只负责调用与汇总，具体检查命令留在项目里 | 每个项目的运行环境不同 |

## 目录

```
SKILL.md                     流程规范：三态 / 三触发点 / 共同底座 / 回写 / 边界
ACCEPTANCE.md                这个技能自己的验收标准（自举）
references/
  acceptance-template.md     验收定义模板（自动栏 + 人工栏 + checks 围栏）
  constraint-change.md       约束变更单格式
scripts/
  check.mjs                  三态检查骨架，零依赖
```

## 快速开始

```bash
# 1. 在你的项目里放一份验收定义
cp references/acceptance-template.md <你的项目>/ACCEPTANCE.md

# 2. 填 A 栏（能跑的写 run，不能的写 unverified）和 M 栏（人看的）

# 3. 判
node scripts/check.mjs --file <你的项目>/ACCEPTANCE.md
```

输出：

```
  A1    PASS
  A2    PASS
  A3    UNVERIFIED  还没接无头浏览器

  3 项：2 通过 / 0 失败 / 1 未验证
  → 结论：未验证，不算做完
```

## 自检

检查器本身也要被检查：

```bash
node scripts/check.mjs --self-test
```

它会现造「通过 / 失败 / 未验证」三个用例，确认三态判定和退出码都对。

## 它不做什么

- 不做自动编排，不替你派活
- 不上传任何东西（除非你明确授权）
- 不替你看效果——人工栏永远留给你
