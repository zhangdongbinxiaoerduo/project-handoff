# project-handoff · 外部判断协同协议

一个 DSH 技能。**DSH 只负责推进项目和把进展推到 GitHub；判断与验收在 Chat 端和人工手里。**

两边不靠转述对齐，靠仓库里的文件对齐。

---

## 权责

| 角色 | 做 | 不做 |
|---|---|---|
| **DSH** | 推进项目、上传进展、复述、按约束执行 | 写验收结论、判自己对错、跑自验、替人裁决 |
| **Chat（网页）** | 读仓库里的真实文件，给意见 | 改文件、直接下令 |
| **人** | 判断、采纳/不采纳、批准约束变更 | 不用自己整理材料 |

**DSH 是交付方，不是验收方。** 这句话决定了整套东西的形状。

## 四步

```
①  DSH 推进 ──▶ 写 docs/progress/012.md ──▶ push
                                      │
                                      ▼
②  Chat 读仓库：进展 + diff + 源码 ──▶ 给意见
                                      │
                                      ▼
③  人判断 ──▶ 写 docs/reviews/012.md（采纳/不采纳/替代哪条约束/复述点）
                                      │
                                      ▼
④  DSH 复述确认 ──▶ 按约束继续做 ──▶ 回到 ①
```

详细操作见 [`docs/workflow.md`](docs/workflow.md)。

## 两个格式

| 格式 | 谁写 | 规矩 |
|---|---|---|
| **进展上传** [`references/progress-upload.md`](references/progress-upload.md) | DSH | 只写事实：做了什么、动了哪些文件（仓库路径）、卡在哪、下一步。**不写结论** |
| **外部意见回写** [`references/external-review.md`](references/external-review.md) | 人 | 意见原文 / 判断（采纳·不采纳·部分采纳）/ 约束影响（新增或替代哪条）/ 复述点 |

两个格式各自只写自己有权写的那部分，所以不会打架。

## 三条硬规则

1. **路径只写仓库路径**——Chat 只能通过 GitHub 看文件，写 `E:\...` 等于没写；
2. **约束变更必须写「替代了哪条旧约束」**——否则 DSH 会同时执行两条打架的指令；
3. **本地优先；不可逆操作（推远端、公开发布、上传截图）单独授权。**

## 目录

```
<项目>/
  docs/progress/     每次上传一份进展，001 起编号
  docs/reviews/      人工回写单，编号与进展对应
  constraints.md     当前生效约束 + 替代记录
```

没有 `ACCEPTANCE.md`，也不需要。项目方自己想定验收标准，那是项目自己的事。

## 这个仓库里有什么

```
SKILL.md                        流程与权责（主文档）
references/
  progress-upload.md            进展上传格式
  external-review.md            外部意见回写格式
  constraints.md                约束登记（含替代记录）
docs/
  workflow.md                   四步操作手册 + 常见失败
  concept.md                    为什么这样设计（含被否掉的方案）
  design-notes.md               推导过程，包括第一版错在哪
  progress/                     进展上传实例
  reviews/                      回写实例
  example/                      一份完整的示例（标注了「示例」）
optional/
  acceptance-template.md        项目方自愿用的验收表格
  check.mjs                     跑命令汇总结果的小工具（不是门禁）
```

`optional/` 里的东西**不是流程的一部分**。DSH 不被要求调用，也不会因为它们不通过就停手——判断不在它手上。

## 这套东西不做什么

- 不做自动编排，不替你派活
- 不替 Chat 看效果、不替人做判断
- 不在没有授权的情况下把任何东西推出本地

### 版本说明

**v1（已废弃）** 是「执行端验收协议」：让 DSH 自己写验收标准、自己跑三态检查、自己输出结论。
问题很直接——**它让执行端自证清白**，等于把判断权交给被判断的人。

**v2（当前）** 把判断权移出 DSH：DSH 只交付事实，Chat 和人负责判断。
保留下来的只有三条硬规则；三态检查降级为 `optional/` 里的可选工具。
