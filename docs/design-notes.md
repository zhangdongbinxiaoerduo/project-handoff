# 设计笔记：这套东西是怎么来的

记录推导过程，包括**被否掉的方案**——不然下次会重复走一遍。

## 起点

最初的问题是：「能不能把 DeepSeek 官方的 chat-demo 做成 DSH 右栏插件？」

查完之后发现：chat-demo 是个纯前端聊天样例，**没有执行层**。把它搬进右栏，等于在一个能干活的环境里再放一个只能聊天的窗口。

于是问题变成了真正的问题：**「会聊天」和「会干活」这两套东西，到底怎么合到一起。**

## 两条融合路线

| | 在 chat 里加深工具 | 给 agent 加对话能力 |
|---|---|---|
| 起点 | 纯对话系统 | 执行系统 |
| 补什么 | 工具、循环、上下文管理 | 理解、追问、计划、呈现 |
| 代表 | ChatGPT（搜索、代码、画布） | Claude Code、DSH |
| 卡点 | 工具一宽，chat 的壳就碎了 | 越来越重、越来越贵、越来越像终端 |

关键发现：**融合的质量不由工具数量决定**，而由四件事决定——何时用、怎么收、怎么回、错了怎么退。

## 拆三层：想过，最后没做

一度设计成三层：窗口层（面向用户）/ 编排层（把话翻成契约）/ 执行层（工具、文件、沙箱）。

看着漂亮，但落不了地，因为：

1. **交接是唯一的难点**，而分层不解决交接，只是把它藏起来；
2. 每多一层，token 翻一倍；
3. 错误归属变模糊：窗口层说派对了，执行层说照做了；
4. 首字延迟变长，产品指标直接压死它。

## 被否掉的方案

| 方案 | 为什么不做 |
|---|---|
| chat-demo 做成右栏插件 | 它没有执行层，搬进去只是多一个聊天框 |
| 三层 agent 自动编排 | 成本高、收益是软的、交接依然难 |
| 每次执行都推 GitHub | 历史脏、噪音大、非代码产物无处放 |
| 用云端执行（Codex Cloud 之类） | 执行搬走了，**文件没跟着走**，反而多一道 push |
| 指望网页 chat 自动扫本地 | 浏览器沙箱不给后台扫盘权限，结构上不可能 |
| 先做「更深的思考层」 | 结果导向下不划算——**验得快 > 想得深** |
| 把结论写成「三行建议」 | 会越积越多互相打架，必须是带替代关系的变更单 |

## 两个关键判断

**一、结果导向 → 验收命令比计划书值钱。**

一条 `node check.mjs` 同时是目标、交接物和停止条件。写得再清楚的计划书，也不如一条能判对错的命令。

**二、交接物是文件，不是对话。**

对话负责想清楚，文件负责传下去。从 chat 回来的话，必须变成文件里的约束，否则等于没回来。

## 关于「执行要靠近文件」

不是「必须同一台机器」，而是**执行者能直接读写同一份权威文件**。

- 本地：文件就在旁边，不需要搬；
- 云端：只要给你完整工作目录，同样成立；
- 网页 chat：碰不到本地，只能上传。

选择本地，是因为**当前不需要搬文件**，不是因为物理上必须。

## 所以最后留下的形态

不拆三层，不自动编排，只做三件小事：

1. **把「什么算通过」写下来**（ACCEPTANCE.md）
2. **用三态诚实地判**（PASS / FAIL / UNVERIFIED）
3. **在决策点生成交接材料，把结论回写成约束**

这三件不解决「融合」这个大问题，但它们让**每一次交接都不丢信息、不发假信号**。

小到能今天用起来，才是它存在的理由。

## 权责反转：第一版错在哪

第一版把「验收」和「交接」做在了一起，并且让 DSH 自己执行验收：它写标准、跑检查、出结论。

**错在把判断权放在了执行端。** 具体三个后果：

1. DSH 只要把标准写松一点点，就永远是「通过」——标准由被判断的人制定；
2. `UNVERIFIED` 变成了体面的出口：什么都标未验证，等于什么都没验收；
3. Chat 和人被降级成「看客」：他们面对的是 DSH 已经整理好的结论，而不是原始事实。

第二版把三件事分开：

| 事 | 归谁 |
|---|---|
| 推进项目、交付事实 | DSH |
| 读事实、指出问题 | Chat |
| 决定采纳与否、批准约束 | 人 |

于是产品形态从「验收协议」变成「协同协议」：
**DSH 不再提供结论，只提供材料；判断在它之外发生。**

这也解释了一个之前没想通的现象：为什么我们一直在给交接材料加字段，却总觉得还差什么——差的是「谁有权写这些字段」。加了权责之后，字段自然就收敛了：

- DSH 只写事实（进度、文件、卡点、下一步）；
- 人只写判断（采纳与否、替代哪条、要复述什么）；
- Chat 不写文件，只给意见。

三条各自独立，就不会互相污染，也不会出现「一份文档既是证据又是结论」的怪东西。
