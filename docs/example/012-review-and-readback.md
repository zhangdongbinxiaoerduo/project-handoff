# 示例：一次完整回写 + DSH 复述

> ⚠️ **这是示例，不是真实发生过的对话。**
> 用来演示第 3 步和第 4 步长什么样：人怎么写回写单，DSH 怎么复述。
> 真实的回写单放 `docs/reviews/`，编号与进展对应。

对应进展：`docs/progress/012.md`

---

## 第 3 步：人工回写（`docs/reviews/012.md`）

```
# 外部意见 012 · 2026-11-14 · 来源 Chat

对应进展：012

意见原文
> 「你把这套东西从验收协议改成了协同协议，但 skill 的 description 里还留着
>   '三态检查' 的说法，模型可能还是按老路走。另外 optional/ 目录没在任何地方
>   说明什么时候该用，等于放了个陷阱。」

人工判断：部分采纳
理由：description 不一致是真的会误导触发；optional 的说明已经写了「不是流程的一部分」，
      但确实没写「什么时候值得用」，这半条也采纳。

约束影响
- 新增 C9：SKILL.md 与 README 不得出现「三态检查」「退出码」作为流程主干描述
- 新增 C10：optional/ 下每个文件开头必须写清「这不是流程的一部分」+ 适用条件
- 不采纳：「删掉 optional/ 整个目录」——有人可能真想要，留着但不推广

需要 DSH 复述确认：是
- 复述点 1：C9 管的是「描述性文字」，还是也包括 optional/check.mjs 里的实现？
- 复述点 2：C10 的「适用条件」要几行？
```

---

## 第 4 步：DSH 复述（写回进展或直接给出）

```
readback：

C9 我理解为主文档（SKILL.md、README）里不再把三态检查写成流程主干；
   optional/check.mjs 的实现保留，因为它是可选工具，代码里有三态是它自己的事。
   → 不确定：docs/workflow.md 里旧的三态说明已删，但 design-notes.md 里还留着历史记录，
     历史记录算不算「描述」？请裁定。

C10 我理解为在 optional/acceptance-template.md 和 optional/check.mjs 开头各加一段：
   一行「这不是流程的一部分」，加 2–4 行「什么时候值得用」。
   → 不确定：是否需要同时更新 README 的目录说明？我倾向同步一行。

不采纳那一条（删 optional/）我不执行。

执行前请确认以上两个不确定点。
```

---

## 人裁定之后

```
裁定：
- design-notes.md 是历史记录，不算「描述」，C9 不管它
- C10 只改 optional/ 两个文件的开头，README 目录说明改一行即可

DSH 按裁定执行，下一份进展写：
「按 C9/C10 改了什么」——不写「已符合要求」。
```

---

## 这个示例想说明什么

| 环节 | 谁在判断 |
|---|---|
| Chat 指出问题 | Chat |
| 采纳一半、驳回一半、写明理由 | **人** |
| 复述 + 提出不确定 | DSH（只确认理解，不评判对错） |
| 最终裁定 | **人** |
| 执行 | DSH |

DSH 全程没有说过一句「这样改是对的」——它只回答「我理解成什么、我不确定什么」。
