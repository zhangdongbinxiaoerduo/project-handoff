# 工作流：从触发到约束生效

协议在别处，这里是**怎么用**。每一步给可直接复制的命令和话术。

## 谁做什么

| 角色 | 干什么 | 不干什么 |
|---|---|---|
| **你（人）** | 触发、批准、判人工栏 | 不用自己整理材料 |
| **执行层**（本机 agent） | 干活、生成材料、复述、按约束改 | 不改验收标准、不自己判人工项 |
| **顾问**（网页 Chat 等） | 读材料、追问、给意见 | 不直接改文件 |

## 第 0 步：每个项目做一次

```bash
# 1. 放一份验收定义
cp references/acceptance-template.md <项目>/ACCEPTANCE.md

# 2. 填 A 栏（能跑的写 run，不能的写 unverified）和 M 栏（人看的 + 留什么证据）

# 3. 定档位：不到半天 / 只跑一次 / 没有第二接手方 → 轻量档，别再往上加
```

## 第 1 步：触发

你只要说一句，不用准备材料：

| 你说 | 执行层生成 |
|---|---|
| 「做到这了，帮我看看」 | 看效果材料：改动清单 + 效果证据 |
| 「卡住了」 | 卡住材料：报错原文 + 试过的动作 + 卡点 |
| 「这个不对」 | 不满意材料：你的原话 + 空白点 |

产物落在 `docs/handoff/<日期>-<序号>.md`，**必须带共同底座五项**：
任务目标 / 基线 / 相关文件 / 待决问题 / 自动验收。

## 第 2 步：把材料给顾问

网页 Chat 只能读链接，所以要先推上去：

```bash
git add -A && git commit -m "handoff: <一句话>" && git push
```

然后把链接和这段一起贴过去：

```
请读这份交接材料：
<仓库链接>/blob/main/docs/handoff/<文件>.md

只回答三件事：
1. 从材料看，这件事卡在哪（或哪里不对）；
2. 你认为下一步最小的动作是什么；
3. 有没有材料里没写、但你必须知道的信息。

不要评价文档写得好不好。
```

## 第 3 步：把回答收回成意见单

复制 `references/opinion-intake.md`，一条意见一行，**必须填「依据」和「是否阻塞」**。

没有依据的意见不要丢，写进「待确认」。

## 第 4 步：人批准

| 决定 | 写法 |
|---|---|
| 采纳 | 写进变更单，标「人已批准 日期」 |
| 驳回 | 在同一行写理由，保留 |
| 先放着 | 留在待确认，不阻塞这一轮 |

**只有批准的才往下走。** 执行层不能自己把意见变成标准。

## 第 5 步：变更单 + 复述

按 `references/constraint-change.md` 写四项：新增 / 替代 / 判定 / readback。

执行层复述后，你要回答它复述里提出的问题（通常是"默认状态下是收起还是记忆上次"这类）。

## 第 6 步：下一轮验收

约束逐条勾：

```
C5  ✅ 窗口数未变，折叠控件存在
C2  ⚠️ 可展开但有 2 处仍全量渲染 → 未落实
C6  ❌ 高风险动作前没有确认
```

**勾不上的不算完。** 自动检查全绿也不行。

## 轻量模式怎么走

跳过第 3–5 步，只做：

1. 触发 → 材料里写「改动清单 + 下一步 + 红绿状态」；
2. 顾问说两句 → 你直接回一句「按这个改」；
3. 不写意见单，不写变更单。

**代价**：下次没人知道你为什么这么改。所以它只适合「跑一次就完」的事。

## 常见失败

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 顾问说打不开链接 | 仓库私有 / 忘了 push | 改公开，或把内容直接贴过去 |
| 意见太空泛（"整体不错"） | 没给问题清单 | 换成第 2 步那段话，逼它回答具体问题 |
| 流程走不动 | 档位太高 | 降到轻量档，别硬撑 |
| 变更单填不出来 | 判定写不出「怎么算通过」 | 说明需求还没想清，回去先定判定 |
| 同一错误改两轮没好 | 在原地重试 | 停下来，按「卡住」触发一次交接 |
