# 工作流：从推进到回写

四步一遍，循环。**每一份产物都是仓库里的文件**，不是聊天记录。

## 第 1 步 · DSH 推进并上传

DSH 干活，然后把这一轮写成 `docs/progress/<编号>.md`：

```
# 进展 012 · 2026-11-14
基线：上一次上传 a1b2c3d

这次做了什么
- 把右栏改成折叠式
- 补了移动端的内边距

动了哪些文件
- src/ui/sidebar.tsx
- src/ui/sidebar.css

当前卡点
无

下一步打算
- 收起状态下的悬浮提示
```

然后推上去：

```bash
git add -A && git commit -m "progress 012" && git push
```

**DSH 到此为止。** 它不写结论、不判对错、不喊「通过」。

## 第 2 步 · Chat 端读

Chat 打开仓库，能看到：

| 能看到 | 不能看到 |
|---|---|
| `docs/progress/012.md` 这一轮的说明 | 你本地没提交的文件 |
| 所有变更的 diff | 你电脑上的运行效果 |
| 源码、注释、提交历史 | 截图（除非你传上来） |
| 之前的进展和回写单 | 你的语气、表情、现场感受 |

给 Chat 的话术（直接复制）：

```
仓库：<仓库链接>
先看 docs/progress/ 里最新的一份，再看对应的 diff。
只回答三件事：
1. 这轮改动里，最可能出错的地方是什么；
2. 有没有和上一轮的说法矛盾的地方；
3. 下一步你会先验证什么。
不要说「整体不错」「建议增加文档」这类话。
```

## 第 3 步 · 人回写

把 Chat 的意见写成 `docs/reviews/<编号>.md`（编号对应进展编号），
格式见 `../references/external-review.md`：

```
# 外部意见 012 · 2026-11-14 · 来源 Chat
意见原文
> 「折叠之后键盘可达性没了」

人工判断：部分采纳
理由：键盘可达是真的，但折叠本身保留

约束影响
- 新增 C8：折叠控件必须能用 Tab 聚焦、Enter 展开
- 不采纳：「取消折叠」

需要 DSH 复述确认：是
- 复述点 1：C8 的适用范围（仅右栏还是全局）
```

**这一步是整套流程的重心。** 判断在这里发生，不在 DSH 那里。

## 第 4 步 · DSH 复述并继续

DSH 读到回写单，只做三件事：

1. 复述约束（用自己的话），把不确定的提问；
2. 人裁定后，按约束执行；
3. 下一份进展里写「按 C8 改了什么」。

```
readback：
  C8 我理解为主界面宽度不变，只调右栏内边距到 12px。
  不采纳那条不执行。
  不确定的点：12px 在移动端是否同样适用？——请裁定。
```

## 常见失败

| 症状 | 原因 | 怎么办 |
|---|---|---|
| Chat 说打不开 | 仓库私有，或没 push | 改公开 / 先 push |
| Chat 的意见太空泛 | 没给具体问题 | 用第 2 步那段话术 |
| 回写单写了一堆但 DSH 执行不动 | 约束不可执行（「好看点」） | 回去让 Chat 给可验证的标准 |
| DSH 越权判自己过了 | 旧习惯（三态验收那一套） | 提醒它：判断不在它手上 |
| 两条约束打架 | 没写替代关系 | 在回写单里补「替代 Cx」 |

## 什么时候可以偷懒

小改动（一两行、当天就完）可以只做第 1 步和第 4 步：

- 上传一份三行的进展；
- 人看一眼说「可以」，DSH 继续。

**不写回写单的代价**：下次没人记得为什么这么改。所以只适合当天闭环的事。
