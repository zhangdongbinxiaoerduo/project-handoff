# 验收定义模板（可选）

> **这不是流程的一部分。**
> 项目方自己愿意定验收标准时，可以拿这份当参考。DSH 不被要求填写、填写了也不代表什么。

## 为什么它是可选的

这套 skill 的权责划分是：**判断权在 DSH 之外**（见 `../SKILL.md`）。

如果让 DSH 自己写验收标准、自己跑、自己出结论，它就从交付方变成了验收方——这是越权。

所以这里只给一张表格模板，谁想用谁用。

## 自动（如果项目方自己想跑）

| 编号 | 检查什么 | 怎么判 |
|---|---|---|
| A1 | 单元测试全绿 | 退出码 0 |
| A2 | 引用的文件都存在 | 无死链 |

想跑就自己跑；结果贴给人看，**不贴给 DSH 当停止条件**。

## 人工（这部分本来就只能人做）

| 编号 | 看什么 | 判据 | 留什么证据 |
|---|---|---|---|
| M1 | 交互生效 | 亲手点一遍 | 截图 + 日期 + 结论 |
| M2 | 观感对不对 | 看着舒服 | 一句结论 + 日期 |

## 机器可读部分（配合 `optional/check.mjs`）

```checks
{"id":"A1","run":"node --test test/"}
{"id":"A2","run":"node scripts/check-links.mjs"}
{"id":"A3","unverified":"还没接无头浏览器"}
```

字段：

| 字段 | 含义 |
|---|---|
| `id` | 对应上表编号 |
| `run` | 判据命令，退出码 0 即通过，非 0 即不通过 |
| `unverified` | 写明为什么判不了 |
| `cwd` | 可选，相对当前目录 |

## 什么时候值得用

| 条件 | 值得 |
|---|---|
| 项目有自动测试 | ✅ 跑一下省事 |
| 交付给人看之前想心里有数 | ✅ |
| 想用它决定 DSH 该继续还是停 | ❌ **不行**，判断不在它手上 |
