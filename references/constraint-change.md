# 约束变更单

从交接里回来的结论，不能是"一段建议"，必须是这张单子。否则执行层拿到的是模糊，不是约束。

## 格式

```
约束变更单 · <日期> · 来自 <哪个决策点>

新增
  C5  右栏只做折叠，不新增窗口
  C6  动手前只在"目标不清 / 方向选择 / 高风险动作"时发问

替代
  C2（原：工具过程不进对话流）
   →  改为：工具过程折叠进对话流，默认收起，可展开

废止
  C4（原：移动端也折叠）—— 理由：与 C5 冲突

判定
  C5 通过 = 主界面窗口数不增加，且右栏存在折叠控件
  C6 通过 = 三类动作前出现一次确认，其余不打断

待确认
  移动端是否纳入本轮（未决，下一轮再定）
```

必需字段：**新增 / 替代 / 判定**。废止和待确认按需写。

## 三条硬规则

1. **新约束必须说明替代了哪条旧约束。** 不写，约束会越积越多，最后互相打架——比模糊更糟。
2. **"判定"必须可检查。** 写"感觉更清爽"不合格，写"窗口数不增加、存在折叠控件"才合格。
3. **写完让执行层复述一遍（readback）。** 复述不对当场驳回，别等下一轮验收才发现理解错了。

## 复述的样子

执行层不写"收到"，而是用自己的话回：

```
readback：
  C5 我理解为主界面窗口数量不变，只在右栏内部折叠。
  C2 已替换：原来完全不进对话流，现在折叠进去、默认收起。
  C4 已废止，与 C5 冲突，移动端这轮不做。
  有一处不确定：折叠控件的默认状态是收起还是记忆上次？——请裁定。
```

最后那行才是复述的价值：**它把理解偏差在动手前暴露出来。**

## 下一轮怎么用

验收清单里逐条勾，勾不上的就是没落实：

```
C5  ✅ 窗口数未变，折叠控件存在
C2  ⚠️ 可展开但有 2 处仍全量渲染 → 未落实
C6  ❌ 高风险动作前没有确认
```
