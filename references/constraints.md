# 约束登记

项目里那一份 `constraints.md` 的唯一作用：**让 DSH 知道当前哪些约束在生效，以及哪条替代了哪条。**

不是验收标准，不是检查清单，不产生结论。

## 格式

```
# 约束

C1  主界面窗口数不增加                     生效 · 人批准 2026-11-10
C2  工具过程折叠进对话流，默认收起           生效 · 替代 C0
C3  右栏内边距统一 12px                    生效 · 人批准 2026-11-14
C4  移动端折叠                           已废止 · 与 C1 冲突
```

一行一条，只写三样：**编号 / 内容 / 状态**。

状态只有三种：

| 状态 | 含义 |
|---|---|
| `生效` | 现在要遵守 |
| `已废止` | 曾经生效，现在别管（保留是为了不让它偷偷回来） |
| `替代 Cx` | 写明替代了哪条，接上历史 |

## 什么时候改

- 只由 `docs/reviews/<编号>.md` 触发；
- 人批准后才写进来；
- 同一轮里新增和替代一起写，别分两次。

## 三条硬规则

1. **新增必带日期和批准人**（就是"人已批准"，不写具体是谁也得写批准这件事）；
2. **替代必写被替代的编号**，不允许出现「C7 覆盖前面相关的那些」；
3. **废止不许删行**，只改状态——删掉之后没人知道它存在过，半年后会有人重新提出来。

## DSH 怎么用

1. 动手前读一遍，只执行 `生效` 的；
2. 发现两条生效约束冲突 → 停下，写进下一份进展的「当前卡点」，等人裁决；
3. 不自行解释「大致是这个意思」，不确定就在复述里问。

## 反例

```
C5  界面要好看一点        ← 不可执行，DSH 只能猜
C6  参考 C2               ← 编号指向不明
C7  全部按上次说的来        ← 「上次」是哪次
```
