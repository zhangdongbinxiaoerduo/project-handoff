# 外部意见回写格式

人工从 Chat 拿到意见后，写成这一份交给 DSH。

**作用不是转达，是裁决。** DSH 看到这个文件，就知道「这是外部判断的结果」，而不是让它自己去判断。

## 格式

```
# 外部意见 <编号> · <日期> · 来源 Chat

对应进展：<编号>

意见原文
> 原话照抄或压缩，不许改写意思

人工判断：采纳 / 不采纳 / 部分采纳
理由：一句，写清为什么

约束影响
- 新增 C7：……
- 替代 C3（原「……」）→ 改为「……」

需要 DSH 复述确认：是
- 复述点 1
- 复述点 2
（否就写：否）
```

## 四条规则

1. **意见原文不许润色**：Chat 说「左边那块太挤」，就写「太挤」，不要翻译成「需要优化间距」——翻译一次就丢一次信息；
2. **判断只能是人给的**：采纳 / 不采纳 / 部分采纳，没有「待定」。待定的放回 Chat 继续问；
3. **采纳就必须落成约束**：写清是新增还是替代；**替代必须写明替代了哪条**，否则 DSH 会同时执行两条打架的指令；
4. **复述点可空，但不能省**：写「否」也是明确表态。

## 部分采纳怎么写

```
人工判断：部分采纳
理由：间距问题是真的，但「左边那块」指的是右栏，不是主界面

约束影响
- 新增 C7：右栏内边距统一 12px
- 不采纳：「缩小主界面宽度」
```

**把「不采纳哪一部分」也写出来**，否则 DSH 会自己猜边界。

## DSH 收到之后做什么

只做三件事，不做第四件：

| 做 | 不做 |
|---|---|
| 复述确认（用自己的话说一遍约束） | 不评判意见对不对 |
| 按约束执行 | 不擅自扩大范围 |
| 在下一份进展上传里写「按 C7 改了什么」 | 不写「已符合要求」 |

## 复述的样子

```
readback：
  C7 我理解为主界面宽度不变，只调右栏内边距到 12px。
  不采纳那一条我不执行。
  有一处不确定：12px 在移动端是否同样适用？——请裁定。
```

最后那句才是复述的价值：**把理解偏差在动手前暴露出来**，而不是做完再说「我以为……」
