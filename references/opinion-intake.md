# Chat 意见单

外部意见（Chat、顾问、同事、你自己随口说的）进流程的第一站。

**意见单不等于约束。** 它只是把散的判断固定下来，等人批准后才进约束变更单。

## 格式

```
意见单 · <日期> · 来源：chat / 人 / 执行层

1. 建议：右栏改成折叠，不要新增窗口
   依据：原文「我不想再开一个窗」/ 链接 / 截图编号
   影响范围：主界面布局、右栏组件
   是否阻塞：阻塞（挡住下一步）
   候选替代：C2（原「工具过程不进对话流」）
   提出者：chat

2. 建议：移动端先不做
   依据：目前只在桌面验证过
   影响范围：无
   是否阻塞：不阻塞（记着就行）
   候选替代：新增
```

## 四条规则

1. **没有「依据」的意见默认不采纳**，只能进「待确认」——凭印象的改动最贵；
2. **一条意见只写一件事**，混在一起就拆开；
3. **「是否阻塞」必须写**：不阻塞的不打断当前这一轮，避免流程压过工作；
4. **意见单不是约束单**：必须由人批准，才能变成 `constraint-change.md` 里的那一条。

## 怎么变成约束变更单

| 意见单字段 | 变更单字段 |
|---|---|
| 建议 | 新增 / 替代 的正文 |
| 候选替代 | 替代（写明替代哪条旧约束） |
| 依据 | 变更单里不需要重复，但**留着备查** |
| 是否阻塞 | 决定这一轮做还是排后面 |

人工批准后，还要补两样东西才能落地：**判定**（什么算通过，可检查）和 **readback**（执行层复述确认）。

## 为什么要有这一层

否则会发生两件事：

- Chat 的意见以「一段话」的形式到执行层手里，被重新理解一遍，然后走偏；
- 意见被转述几次以后，已经没人记得它当初的依据是什么。
